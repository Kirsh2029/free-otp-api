Rechecked **November 5, 2026, approximately 3:20–3:30 p.m. America/New_York (20:20–20:30 UTC)** with ordinary public HTTPS and standard headless Puppeteer. The audit used no authenticated inboxes, challenge solving, stealth plugins or access-check bypasses. Counts below are dated observations, not current inventory guarantees.

**Fresh SMS delivery is unverified for all seven providers.** No new SMS was sent or received during this audit. Public number listings, historical messages and extracted old OTPs establish parsing compatibility only. They do not establish that a listed number receives new messages from a particular sender or carrier.

## Runtime behavior and diagnostics

All historical source IDs and country enum values remain recognizable. `providers` contains enabled sources; source-specific active countries exclude confirmed unavailable integrations. `/api/providers` reports `unavailableCountries` and the separate verification checks. Selecting an excluded country or disabled source returns 503 before browser work.

Phone numbers are normalized to E.164 digits without a leading `+`, including the calling code. National inputs are interpreted for the selected country. URLs and pagination destinations are restricted to provider origins declared in code. OTP extraction preserves leading zeros and avoids taking fragments from a longer digit sequence.

Listing pagination is iterative, deduplicated, loop-detected and bounded by `MAX_PROVIDER_PAGES` (default 50). The whole collection shares a `BROWSER_TASK_TIMEOUT_MS` deadline (default 60 seconds). Exceeding either bound fails explicitly, and a failed refresh does not overwrite a complete Redis cache with partial results. Transient failures receive bounded retries; access denials and unavailable inventory surface without repeated probing.

Inbox retrieval defaults to one read. Optional polling is bounded; page selection follows provider support. The API applies `since`/`ago`, literal case-sensitive `match`, and `limit`. `since=0` reads available history. `requested.timeFilter` describes the effective filter; `requested.agoText` is omitted for an absolute `since` filter.

Successful native reads report actual `diagnostics`: DOM row count, parsed count, drop reasons, time/matcher exclusions, matched/returned count, page, polling count and observed timestamp range. Counts describe the latest actual read, not the sum of repeated snapshots. Providers without raw parsing metadata do not receive fabricated raw/drop counters. If rows exist but all fail parsing, the response is 502 with the available diagnostics. A genuine empty inbox or a readable inbox with no filter match is a successful empty result; these conditions differ from an upstream failure. API responses use `Cache-Control: no-store`.

The message endpoint's `diagnostics.deliveryStatus` remains `unverified`. It does not change merely because historical messages or old OTPs were parsed.

## Rechecking an individual number

1. List numbers for an enabled source and active country; preserve the returned source and phone number.
2. Read that same inbox with `since=0`, then inspect observed counts, parse drops and newest-message time. A stale archive may parse correctly without receiving fresh messages.
3. Use [`POST /api/delivery-tests` and `GET /api/delivery-tests/:id`](../README.md#controlled-fresh-sms-check) for a controlled dummy-message check. The API reads a baseline and generates the text; a user must send it externally. No SMS is sent by Number API.
4. Keep the test `pending` or `expired` unless its unique marker and expected code text are newly observed in the provider's parsed inbox. `received` is evidence for that specific test; `evidence.otpMatched` separately reports the extractor's result.

Automated parser tests and readable public pages do not replace sender-to-provider-to-API delivery evidence. The current audit contains no such fresh receipt.
