# Provider compatibility audit

Checked **2026-11-05** using ordinary public HTTPS requests and standard headless Google Chrome through Puppeteer 25.16. No stealth plugins, CAPTCHA solving, authenticated sessions, proxy rotation, or other access-check workarounds were used. A rendered homepage alone does not count as a working scraper.

“Verified” means that the application handler actually returned a nonempty country listing **and** parsed a real public inbox, including valid timestamps and OTP extraction, on that date. These are point-in-time observations, not a promise of delivery or continued availability. No SMS was sent, no account was created, and no third-party account was accessed. Inbox contents and OTP values are deliberately omitted from this report.

## Runtime behavior

All seven historical identifiers remain in `Sources`. `providers` contains enabled providers; `GET /api/providers` reports status, reason and verification date. Disabled sources are rejected before starting a browser. Providers are never declared working merely because HTTP or DNS responds.

Phone numbers are returned as E.164 digits without `+`, including their country calling code. Input formatting and national-number compatibility are handled centrally. Provider links retain their external domains. Malformed cards are filtered, country calling codes are validated, URLs are resolved with `URL`, and all pagination/navigation destinations are restricted to trusted origins declared in code. Timestamps use milliseconds since the Unix epoch; unknown and implausibly future dates are discarded. OTP extraction preserves leading zeros and avoids taking a short slice from a longer digit sequence.

Listing pagination is iterative, deduplicated, loop-detected and bounded by `MAX_PROVIDER_PAGES` (default 50). Exceeding the bound raises an explicit error rather than caching an incomplete result. The complete multi-page listing shares one overall `BROWSER_TASK_TIMEOUT_MS` deadline (default 60 seconds); expiry cancels its active browser page and returns 504. Transient listing failures use bounded `PROVIDER_RETRIES` (default 2); access denials and unavailable inventory are surfaced without repeated probing. Failed cache refreshes preserve the last valid cached data until its Redis TTL expires.

Inbox retrieval supports provider-specific page selection, string matching, `since`/`ago` time filters and result limits. The API performs one pass by default; a requested wait is bounded. There are no recursive infinite polling loops. A valid inbox with no matching message returns an empty result; a provider/page failure returns an error. The API does not infer whether a listed number can receive a newly sent SMS.

## Rechecking

Install the project's dependencies and start Redis as described in the README. `npm test` covers provider registration, disabled-source behavior, bounded pagination, origin checks, failure propagation, time/text matching and extraction. Those deterministic checks do not substitute for live provider tests.

For a live check, call `GET /api/list/UK?source=anonymsms.com`, choose a returned number, and request `GET /api/UK/PHONE?source=anonymsms.com&since=0`. Repeat with a supported country and source; page 2 is `&page=2`. Use the exact routes in `/docs` if configuring a different API path. Source availability, public stock and website terms can change independently; retain HTTP/status evidence and parsed counts without logging message contents or OTP values.
